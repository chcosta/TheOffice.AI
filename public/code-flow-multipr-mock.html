Multiple PRs per dev card · the add-PR experience

Dev is singular (one dev/<slug> workbench per work item). PRs are plural — each is a proposal derived from the dev branch, on its own pr/<slug>-<label> branch in exactly one worktree. The lower surface always focuses one PR at a time; a plain-text PR rail switches focus and adds PRs.

Branch & worktree invariant. Every PR gets a distinct branch — pr/fix-scaler, pr/fix-scaler-followup, … — each attached in exactly one worktree. Because no branch is ever wanted in two places, dev↔pr and pr↔pr collisions are structurally impossible regardless of how many PRs a card has.
