Code Flow — the dev ↔ pr model

One change lives on two branches that flow into each other. You always know where you're working and there's only ever one right next move.

Dev card — your workbench
Where you and dev agents build. All hand edits happen here. Never blocked by review.
dev/fix-scaler
PR card — the review copy
Where reviewer & steward agents run and where feedback commits land. You rarely hand-edit here.
pr/fix-scaler
main — the target
The PR merges pr/… into main. Dev never touches main directly.

Why this can't collide or go detached.
  • One branch, one worktree. dev/… only ever lives in the dev worktree; pr/… only in the pr worktree. Git's "already used by" fatal becomes impossible.
  • No borrowing. The dev card never checks out the PR's branch — so the old 🔀 PR branch button is removed.
  • Movement is explicit & directional. Promote (→) and Pull review (←) are the only ways commits cross, and the rail shows ahead/behind so you always see state.
  • Agents have a home. Dev agents → dev worktree. Reviewer/steward agents → pr worktree. Their reports surface on the matching card.
